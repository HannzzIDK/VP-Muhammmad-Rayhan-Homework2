# Composition Rationale - Quest Habit Tracker 

Berikut adalah daftar widget yang diekstrak untuk menerapkan *state hoisting* dan memisahkan tanggung jawab (*separation of concerns*) pada layar utama:

1. **`UserStatsHeader`**
   * **Trigger:** Readability. Memisahkan layout bagian atas (header statistik) dari `DashboardScreen` agar metode `build` utama tidak terlalu panjang dan lebih mudah dibaca.
   * **Owns:** Struktur UI statis untuk menampilkan Level, bar/teks EXP, dan jumlah Koin.
   * **Reports Upward:** Tidak ada (widget pasif).

2. **`QuestCard`**
   * **Trigger:** Reuse. Komponen ini adalah fondasi visual terkecil untuk sebuah *quest*. Dirancang agar dapat digunakan berulang kali untuk berbagai jenis *quest* (Main/Side).
   * **Owns:** Penataan visual (*Card*, warna latar belakang saat selesai, *typography*), dan logika pergantian ikon/tombol berdasarkan status `isCompleted`.
   * **Reports Upward:** Melaporkan event interaksi pengguna (tombol "Klaim" ditekan) ke atas melalui properti fungsi `onClaim`.

3. **`QuestSelection`**
   * **Trigger:** Readability & Reuse. Menangani perulangan (*looping*) seluruh daftar quest sehingga `DashboardScreen` tidak perlu mengurus logika iterasi antarmuka secara mentah.
   * **Owns:** Logika pemetaan (*mapping*) dari list model data `Quest` menjadi sekumpulan widget `QuestCard` di dalam sebuah `Column`.
   * **Reports Upward:** Meneruskan fungsi pelemparan *index* melalui `onClaim(index)` agar `DashboardScreen` tahu *quest* mana yang diselesaikan.

4. **`EmptyQuestView`**
   * **Trigger:** Readability. Memindahkan blok UI "layar kosong" agar kondisi *if/else* atau *ternary* pada parent widget lebih bersih dan terisolasi.
   * **Owns:** Aset visual statis (seperti `Icon`) dan teks pesan bahwa daftar tugas sedang kosong.
   * **Reports Upward:** Tidak ada.
